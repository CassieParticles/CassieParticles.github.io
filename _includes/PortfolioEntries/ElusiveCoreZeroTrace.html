Elusive Core: Zero Trace

Elusive Core: Zero Trace was a stealth-platform that I worked on as part of the team Cosmic Coda over 7 months, the project started out as part of our professional project module in third year. We were a team of 8 developers over several disciplines, where I was one of two programmers, we worked with pocket sized hands to create a game from the prompt "X meets Y", after the module was finished, we decided to enter into dare, where we got to the finalists stage, meaning we were able to further work on the game for another 2 months. During this project I learned many useful skills, such as writing more maintainable code, creating tools for designers to use within levels, and documentation keeping

I created the enenmy behaviour within the game, including the guards, the guard behaviour was done using a finite state machine, with each state being an object, allowing new behaviours to be added without affecting the flow or behaviour of existing states

The boss spotlight was one of the main features we wanted for dare, the design of this system was influenced by our designer, since he would need maximum control over the behaviour of the spotlight, but we wanted to avoid making him write code, so I created a system using triggers to make the spotlight change it's behaviour, with anchors controlling the spotlights behaviour, This was designed with the mentality that he would want more ways to control the spotlight as the project developed which influenced the design of the spotlight system to allow for this

The hacking system was created to combat the player not having enough ways to influence the world, it was created in two parts, with our other programmer creating the player interaction side, and me creating the hackables that the player would hack, since our designers would almost certainly want new hackable objects as the project went on it was imperitive the hackables be designed so that creating new hackable objects could be done withotu requiring any restructuring of other parts of the code, and so I designed the system to ensure this could be done

As well as programmer, I was also this projects source control admin, this meant I was in charge of managing and maintaining our git repository, to reduce issues with this, I asked our team to follow the git-flow workflow, where all changes are done on feature branches, before being merged into a development branch. In addition to this, I created training materials for using git-flow with various git guis, including git kraken, github desktop and sourcetree
